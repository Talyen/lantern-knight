# Agent workflow

Prototype iteration is the default. Preserve unrelated edits. [Development](docs/development.md) owns the edit loop; small sequential edits need no task registry or evidence database.

Start with the relevant [owner](docs/architecture.md#owners) or [guide](README.md#documentation) and matching [skill](.agents/skills/README.md). Use `npm run --silent docs:read -- --search '<phrase>'` when the guide is unknown; `<file.md>#<heading>` reads a bounded section, and a path alone lists anchors and section sizes. Follow continuation commands when needed. Search that owner's paths before opening code. [Agent context](docs/development.md#agent-context) owns discovery and output guidance.

Use one isolated worktree and task branch per implementation chat, starting from committed local `main` unless the user specifies another base. Reuse a suitable worktree and verify `git rev-parse --show-toplevel` and `git worktree list` before editing. [Task coordination](docs/task-coordination.md) owns isolation and the automatic integration lock. Zero inter-chat messages is the default; message only for a concrete unresolved dependency or conflict that repository evidence cannot answer. Finished chats leave the coordination loop; unsolicited routine messages require no response or renewed work.

Finish with fresh `npm run check`; also run `npm run docs:check` for prose edits. [Verification](docs/verification.md) owns high-value tests (zero new tests is valid), CI/browser coverage and asset/native/visual checks. Report actual coverage. Each chat commits its reviewed task changes and integrates into clean local `main` under `npm run integration:lock -- <command> [args...]` and [standing commit authorization](docs/task-coordination.md#handoff-and-commits). Hold the lock through incorporating current `main`, verification and advancing `main`. The integration lock checkpoints valid saved scene files, asset review decisions and new immutable ground profiles in `main` before integrating, so ordinary editor saves need no user cleanup. Preserve other dirty work; if blocked, leave the task committed on its branch and report why. After successful integration, `integration:lock` automatically deletes and unregisters only the invoking task worktree, including local-only files and build outputs, while retaining its branch under the [cleanup policy](docs/task-coordination.md#handoff-and-commits). Pass `--keep-worktree` before the integration command when requested work or a preview still needs the checkout. Report the hash, integration and cleanup status, then stop; pushes, PRs, publication other than task-scoped asset packs, and other destructive cleanup require separate authorization.

# Artwork and assets

Before artwork/texture generation, editing, replacement or art direction, apply `lantern-art-direction` at `/Users/ryanmcintire/.codex/skills/lantern-art-direction/SKILL.md`. Every generation prompt includes the canonical `references/canon/clean-ink-style.prompt.txt` block, highest native resolution/quality and literal `gpt-image-2.5 sunburst`. Inspect outputs under [canonical style](references/canon/clean-ink-style-sources.md); preserve original sources and canonical hero artwork.

For production composition, follow [scene policy](docs/scene-design.md) and [lantern-scene-design](.agents/skills/lantern-scene-design/SKILL.md). Preserve existing art direction; design advice permits valid experiments.

[Assets](docs/assets.md) owns preparation, immutable delivery, external cache budgets and active leases. Keep code, focused tests, small recipes and current docs in Git; generated packs/catalogs, staging, captures, logs and history stay outside Git. Ordinary code/CI consumes `assets/lock.json`; do not crawl the source library, cache, dependency lockfile or generated packs for context. Use `npm run assets:inspect -- <asset-id>` for bounded details.

Asset prototypes use source-verified `npm run assets:prepare -- --ids <asset-id>`. Builds/CI never regenerate artwork. Agents may use `npm run assets:publish` or `npm run assets:publish-files` when ready to share assets within their assigned task, without separate approval. Follow source verification, artwork inspection and immutable delivery checks in [Assets](docs/assets.md#preparation-and-publication).
