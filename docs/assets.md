# Asset ownership and verification

The shared source authority is `~/Documents/Asset Library/2d Assets/Lantern Knight`, backed up in iCloud. `ASSET_LIBRARY_ROOT` selects the parent Asset Library folder, normally `~/Documents/Asset Library`; tools append the source index's `libraryDirectory`, currently `2d Assets/Lantern Knight`. Original archives and current project originals remain unchanged. The compact source index has an 80 KiB authored-input cap and records archive/loose-file identities and paths as hints; [automatic recovery](source-recovery.md) handles reorganization without accepting different bytes.

Code, authoring recipes, the pack pin and small controlled fixtures belong in Git. Raw collections, expanded catalogs, atlases, registration arrays, captures and logs remain outside the checkout. The two original hero reference images are explicit repository exceptions; their bytes and the canonical Clean INK prompt are preserved.

The Last Tended Light Graveyard kit uses the small [authored registration recipe](../authoring/graveyard-art.json). Selected native PNGs, exact prompts and provenance remain in the external `last-tended-light-v1` source group. Preparation preserves native RGB, removes generated low-alpha backdrop contamination with a recorded alpha remap, and pads cutouts without scaling their drawings. Native resolution and requested model are recorded independently; the built-in tool does not expose model routing or size controls.

## Preparation and publication

`assets:prepare` reads only selected members from verified source archives, creates derivatives in a reserved external workspace, and verifies source fidelity, corrected walk drawings, alpha-aware atlas packing, registrations and generated freshness. Library stills without supplied physical registration use a provisional 256 pixels per metre reference and source/alpha-bound contact estimates. This does not certify physical dimensions. Supplied numeric PPU and current import corrections take precedence; inherited PPU uses the documented reference convention for these newly introduced visual actors. No source art is enlarged or regenerated.

It prepares the active Game catalog and the broader developer authoring catalog. Current world-library selections are frozen in the small [library recipe](../assets/library-packs.json); supplemental archive identities live in [library sources](../assets/library-sources.json). Runtime atlas rectangles, clip timing and mixed frame registrations are preserved. Expanded catalogs and import receipts stay in the prepared pack. Source companions, rejected/superseded tests, preview media and title/loading sequences are excluded from world preparation. The fixed-view studies remain provisional; delivery changes do not grant production-art approval.

Python 3 with OpenCV 5.0.0 and NumPy 2.0.2 is required only for preparing walk fields. Normal builds require Node and the pinned prepared pack. Finalization requires a macOS or Windows host for packaged validation; publication requires the GitHub CLI (`gh`) authenticated with release-write access to the project repository and a working public download path.

`assets:finalize` reuses an intact matching preparation, or prepares current inputs once if none exists. It validates the exact candidate and retains source-bound visual evidence before publication. When fresh preparation proves an identical payload, finalization retains the published archive and updates only accepted preparation provenance. Changed payload publication creates an immutable content-identified release, verifies its downloadable byte size and SHA-256, then atomically changes `assets/lock.json`. Existing published revisions are immutable. A failed preparation/upload/download or a recipe change during publication leaves the previous pin intact. Release files must remain below 2 GiB.

The pack contains selected current runtime pages/manifests, lighting/surface companions, walk data, coverage data and validation receipts. It excludes source archives, staged source images, historical generations and diagnostics. Game and Dev still ship their own catalog selections.

## Consumption

`assets:ensure` validates authored asset intent and the complete published file inventory. Preparation-tool edits can consume an existing modern pin; explicit candidate preparation still binds the full recipe and source verification. Version 2 pins retain the original archive recipe/hash/inventory and add the accepted recipe input hashes and payload-equivalence digest. Existing version 1 pins and archives remain readable; published archive bytes are never rewritten. Missing or corrupt packs are downloaded by their exact revision and verified before extraction. Unsafe paths, links, duplicate/case-colliding entries, oversized payloads and wrong hashes are rejected. Valid local copies work offline.

Normal commands hold a process lease across tests, builds or the development server. Vite reads the prepared public directory from the external cache. Browser and Node consumers share typed registration parsing; source-free checks validate contracts, pixels' stored hashes, quality, bindings, coverage, geometry and companion registration. They do not claim to verify original bytes unavailable to CI.

## Runtime composition boundary

Runtime layouts, prop positions, collision geometry, framing in [camera defaults](../src/content/camera.json), and lighting presets are independent of preparation. [The recipe manifest](../assets/recipe.json) owns preparation order, exact artwork-producing inputs and relevant dependency versions. [Recipe hashing](../tools/assets/recipe.ts) includes the data-only [preparation catalog](../src/content/asset-catalog.ts) and preparation helpers. Delivery, cache, publication and subprocess-supervision changes do not invalidate artwork. Full authored-source digests in validation and build evidence retain tooling provenance separately. Modern outgoing snapshots compare the recipe's authored data inputs against the accepted pin. Preparation-tool changes alone do not require artwork publication. Legacy pins retain their stricter recipe checks. Runtime actor tint and clip bindings in `src/content/visuals.ts` do not invalidate artwork; bindings must still resolve against the pinned pack. [Bake calibration](../src/assets/camera.json) owns the artwork projection/registration contract; changing it still invalidates the pack. Coverage is prepared for catalog props independently of placement. [Ground overlay selection](../authoring/ground-overlays.json) owns the supported prepared overlays; adding an unprepared overlay requires authoring, while moving an existing one does not.

Material preparation does not bake paths, graves or decals. Optional `npm run assets:prepare -- --proof` also produces the native ground-panel contact proof and its receipt outside the shared payload. Proof-only scene/code changes do not invalidate the shared pack. Source-fidelity and runtime sampling/construction checks remain required.

## Cache and retention

The cache is `~/Library/Caches/LanternKnight` on macOS, the XDG cache directory on Linux, or Local AppData on Windows. `LANTERN_CACHE_ROOT` can select another external cache. Its total budget is 4 GiB. Preparation and publication share immutable candidate pages through hard links, counted once by physical file identity within a cache entry. Reservations include downloads, extracted assets, preparation intermediates and diagnostics. Old unused entries are evicted; active files are protected. Operations fail clearly when protected data and necessary working space cannot fit. Compressed downloads and transient files are removed after use.

Published deletion is explicit through `assets:clean`. It first resolves this checkout’s pin, remote-main, open-PR head and supported-release pins, and refuses deletion if reference inspection fails. It does not scan other local checkouts; check for locally retained revisions before retiring a pack that only those checkouts reference. It never deletes the shared source library. Initially no game releases are supported; maintain the short supported-tag list when releases enter or leave support.

Successful checks use summaries. Failures or explicit capture requests retain bounded external diagnostics. Hosted failure artifacts expire after three days. Do not commit output to preserve a review history.

Native canvas, pivot and density are recorded per frame, including mixed ready/action Sweep densities. Runtime geometry uses these values without resizing, mirroring or adding root motion.

LMB requests alternating Sweep and Lunge, beginning with Sweep. Attacks finish before the next buffered attack or dodge; no combo or finisher scaling applies. Alternation survives damage, dodges and area transitions but is not saved. Directed holds in `authoring/hero-actions.json` determine action duration and damage/pulse boundaries at 60 Hz. Sweep lasts 54 ticks with damage at ticks 18–24; Lunge lasts 42 ticks with damage at ticks 12–16. These windows are shared across all action directions. Dodge lasts 30 ticks and travels 2.1 metres only in cels 4–5 (ticks 6–14), sharing those travel ticks with invulnerability. Hit lasts 24 ticks, Lantern 60 ticks with its pulse at tick 24, and Death 90 ticks before reset. Source handoff timing and original raster bytes remain preserved separately.

These are supplied TEST assets with approximate registration and known pose/endpoint differences, not newly certified production artwork. At 3840×2160 and 9 metres vertical span, the least-dense hit pose has 0.901 native pixels per output pixel; all poses reach at least 1× from 9.99 metres. The quality gate checks this selected native baseline separately while retaining previous headroom requirements for existing assets. No raster enlargement is used to claim higher native resolution.

## Local preparation review

Prototype asset work finishes locally. Run `npm run assets:dev -- --ids <asset-id>` (or `npm run assets:prepare -- --ids <asset-id>`) to prepare only selected owners and required dependencies. The recipe declares common inputs once, plus each step's IDs, owned inputs and dependencies. Full packs and local overlays share one step executor. Successful steps retain immutable output hashes and selected source identities; unchanged dependencies reuse those outputs. New steps run their own freshness/fidelity check once. A small media import runs its media step, without hero, room, lighting or animation baking, archive creation, packaging or upload.

Each checkout has an immutable, leased prototype layer over a verified pinned or previously prepared base. Preview commands and affected asset-backed tests consume that layer automatically. Existing runtime images remain usable when preparation tooling or formatting changes; ordinary coding does not read source artwork or demand publication. Stop a task-owned warm browser with `npm run prototype:stop` when finished. Original sources and the published pin remain unchanged.

Full `npm run assets:prepare` is explicit authoring/integration. Its incremental step cache is inside the existing reserved preparation entry; matching inputs and outputs are reused, while changed steps and dependents are rebuilt. Published assets and cached step sources are never mutated through hardlinks. Full source verification, cache bounds, leases and fail-closed corruption handling remain required.

### Delivery publication

Run `npm run assets:finalize` only for an explicitly requested integration/delivery batch. It owns regular integrity checks and relevant delivery journeys for a frozen candidate. Selection follows changed prepared output inventories, rather than blanket helper/recipe changes; passing phases can resume while source, output bytes and retained evidence match. Inspect its exact returned captures; then use its printed `--reviewed` identifier. Prototype task completion does not imply publication, scene aesthetic approval, hosted CI or another platform's behavior.

Add `--bundles` to both finalization and its reviewed publication to produce a version 3 pin. Immutable bundles separate hero, consuming rooms, developer-library data, common resources and small media. Unchanged content bundles reuse their existing release identities; a video change uploads only its media bundle and any changed common metadata. Version 1/2 pins and their original archive bytes remain readable. Every downloaded archive and merged inventory retains hash, size, path, duplicate, symlink and case-collision checks.

One owner publishes a delivery batch after contributors declare relevant source stable. Worktrees can iterate against separate prototype layers; do not overwrite another layer or preparation. Commits, pushes, application promotion and deletion remain separately controlled. Keep original sources, canonical artwork and gameplay IDs intact. Failed validation or public download verification leaves the prior pin untouched. Retire old releases only through the retention workflow.

## Current animation treatment

The prepared registration contains clip/direction-specific guarded transition fields, mixed-frame canvas/pivot/density mappings, original holds, bounded presentation offsets and weighted walk holds. The small `authoring/hero-motion.json` recipe owns native-space correspondence markers, reviewed sword segments and visibility, signed rotation, residual offsets and loading/release/settling treatments. Torso markers seed correspondence; they do not establish measured anatomical retargeting or root motion. Original four-direction Weighted Walk holds are preserved; new cardinal runs use reviewed loading holds within their supplied 40-tick cycle, retaining the balanced six-drawing D rhythm.

Runtime defaults to guarded treatment, stabilization and rigid-sword protection with directed action timing. Loaded poses hold before accelerating; release is fast, recovery slows into rest and idle breathes gently. Body coherence remains guarded by silhouette/color checks. Reviewed fully hidden swords permit body-only warp; uncertain short occluded blades, changing visibility and incoherent poses retain held drawings. Rigid sampling follows the reviewed blade segment, respects the native hand/occlusion paint and uses the same signed rotation for color, lighting, shadows and focus. Native projected length changes are retained. Raster sources, pivots and densities are unchanged.

Dev comparison offers Treatment (identical directed timing, corrected versus held drawings) and Timing (directed versus imported rhythm on shared elapsed time). The visual timeline shows directed drawing boundaries, damage windows and lantern pulse; status explains held fallbacks. Seeking is silent and preview controls do not write saves. Field textures stay below 4096 pixels per dimension; generated data and captures remain external. Optical flow cannot supply missing poses: rear death drawings end kneeling, and some partially occluded equipment cannot be safely interpolated.
