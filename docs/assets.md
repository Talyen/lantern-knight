# Asset ownership and verification

The shared source authority is `~/Documents/Asset Library/2d Assets/Lantern Knight`, backed up in iCloud. `ASSET_LIBRARY_ROOT` overrides the library location. Original archives and current project originals remain unchanged. The compact source index has an 80 KiB authored-input cap and records archive/loose-file identities and paths as hints; [automatic recovery](source-recovery.md) handles reorganization without accepting different bytes.

Code, authoring recipes, the pack pin and small controlled fixtures belong in Git. Raw collections, expanded catalogs, atlases, registration arrays, captures and logs remain outside the checkout. The two original hero reference images are explicit repository exceptions; their bytes and the canonical Clean INK prompt are preserved.

The Last Tended Light Graveyard kit uses the small [authored registration recipe](../authoring/graveyard-art.json). Selected native PNGs, exact prompts and provenance remain in the external `last-tended-light-v1` source group. Preparation preserves native RGB, removes generated low-alpha backdrop contamination with a recorded alpha remap, and pads cutouts without scaling their drawings. Native resolution and requested model are recorded independently; the built-in tool does not expose model routing or size controls.

## Preparation and publication

`assets:prepare` reads only selected members from verified source archives, creates derivatives in a reserved external workspace, and verifies source fidelity, corrected walk drawings, alpha-aware atlas packing, registrations and generated freshness. It prepares only active Game and developer catalogs. The fixed-view studies remain provisional; delivery changes do not grant production-art approval.

Python 3 with OpenCV 5.0.0 and NumPy 2.0.2 is required only for preparing walk fields. Normal builds require Node and the pinned prepared pack. Finalization requires a macOS or Windows host for packaged validation; publication requires the GitHub CLI (`gh`) authenticated with release-write access to the project repository and a working public download path.

`assets:finalize` reuses an intact matching preparation, or prepares current inputs once if none exists. It validates the exact candidate and retains source-bound visual evidence before publication. `assets:publish` is a compatibility alias for this same workflow. When fresh preparation proves an identical payload, finalization retains the published archive and updates only accepted preparation provenance. Changed payload publication creates an immutable content-identified release, verifies its downloadable byte size and SHA-256, then atomically changes `assets/lock.json`. Existing published revisions are immutable. A failed preparation/upload/download or a recipe change during publication leaves the previous pin intact. Release files must remain below 2 GiB.

The pack contains selected current runtime pages/manifests, lighting/surface companions, walk data, coverage data and validation receipts. It excludes source archives, staged source images, historical generations and diagnostics. Game and Dev still ship their own catalog selections.

## Consumption

`assets:ensure` validates the accepted preparation recipe and complete published file inventory. Version 2 pins retain the original archive recipe/hash/inventory and add the accepted recipe input hashes and payload-equivalence digest. Existing version 1 pins and archives remain readable; published archive bytes are never rewritten. Missing or corrupt packs are downloaded by their exact revision and verified before extraction. Unsafe paths, links, duplicate/case-colliding entries, oversized payloads and wrong hashes are rejected. Valid local copies work offline.

Normal commands hold a process lease across tests, builds or the development server. Vite reads the prepared public directory from the external cache. Browser and Node consumers share typed registration parsing; source-free checks validate contracts, pixels' stored hashes, quality, bindings, coverage, geometry and companion registration. They do not claim to verify original bytes unavailable to CI.

## Runtime composition boundary

Runtime layouts, prop positions, collision geometry, framing in [camera defaults](../src/content/camera.json), and lighting presets are independent of preparation. [The recipe manifest](../assets/recipe.json) owns preparation order, exact artwork-producing inputs and relevant dependency versions. [Recipe hashing](../tools/assets/recipe.ts) includes the data-only [preparation catalog](../src/content/asset-catalog.ts) and preparation helpers. Delivery, cache, publication and subprocess-supervision changes do not invalidate artwork. Full authored-source digests in validation and build evidence retain tooling provenance separately. The outgoing snapshot selects its recipe algorithm; pre-manifest snapshots retain their legacy checks. Runtime actor tint and clip bindings in `src/content/visuals.ts` do not invalidate artwork; bindings must still resolve against the pinned pack. [Bake calibration](../src/assets/camera.json) owns the artwork projection/registration contract; changing it still invalidates the pack. Coverage is prepared for catalog props independently of placement. [Ground overlay selection](../authoring/ground-overlays.json) owns the supported prepared overlays; adding an unprepared overlay requires authoring, while moving an existing one does not.

Material preparation does not bake paths, graves or decals. Optional `npm run assets:prepare -- --proof` also produces the historic ground-composition proof and its receipt outside the shared payload. Proof-only scene/code changes do not invalidate the shared pack. Source-fidelity and runtime sampling/construction checks remain required.

## Cache and retention

The cache is `~/Library/Caches/LanternKnight` on macOS, the XDG cache directory on Linux, or Local AppData on Windows. `LANTERN_CACHE_ROOT` can select another external cache. Its total budget is 4 GiB. Reservations include downloads, extracted assets, preparation intermediates and diagnostics. Old unused entries are evicted; active files are protected. Operations fail clearly when protected data and necessary working space cannot fit. Compressed downloads and transient files are removed after use.

Published deletion is explicit through `assets:clean`. It first resolves this checkout’s pin, remote-main, open-PR head and supported-release pins, and refuses deletion if reference inspection fails. It does not scan other local checkouts; check for locally retained revisions before retiring a pack that only those checkouts reference. It never deletes the shared source library. Initially no game releases are supported; maintain the short supported-tag list when releases enter or leave support.

Successful checks use summaries. Failures or explicit capture requests retain bounded external diagnostics. Hosted failure artifacts expire after three days. Do not commit output to preserve a review history.

The screen-D run intentionally uses six drawings; the other new runs use eight. All run cycles remain 40 ticks. Native canvas, pivot and density are recorded per frame, including mixed ready/action Sweep densities. Runtime geometry uses these values without resizing, mirroring or adding root motion.

LMB requests alternating Sweep and Lunge, beginning with Sweep. Attacks finish before the next buffered attack or dodge; no combo or finisher scaling applies. Alternation survives damage, dodges and area transitions but is not saved. Directed holds in `authoring/hero-actions.json` determine action duration and damage/pulse boundaries at 60 Hz. Sweep lasts 54 ticks with damage at ticks 18–24; Lunge lasts 42 ticks with damage at ticks 12–16. These windows are shared across all action directions. Dodge lasts 30 ticks and travels 2.1 metres only in cels 4–5 (ticks 6–14), sharing those travel ticks with invulnerability. Hit lasts 24 ticks, Lantern 60 ticks with its pulse at tick 24, and Death 90 ticks before reset. Source handoff timing and original raster bytes remain preserved separately.

These are supplied TEST assets with approximate registration and known pose/endpoint differences, not newly certified production artwork. At 3840×2160 and 9 metres vertical span, the least-dense hit pose has 0.901 native pixels per output pixel; all poses reach at least 1× from 9.99 metres. The quality gate checks this selected native baseline separately while retaining previous headroom requirements for existing assets. No raster enlargement is used to claim higher native resolution.

## Local preparation review

A replacement pack can be prepared and exercised locally before publication. Use `npm run assets:prepare`, then append `--local` to asset-backed checks/builds/smokes. This explicitly selects the validated preparation entry, checks its recipe and complete inventory, and holds a cache lease. Ordinary development and CI continue to use `assets/lock.json`; local review does not change that pin. Requested runtime-asset tasks authorize publication and pinning as part of completion, without another user approval prompt; explicit preview-only experiments stay local. This includes active TEST/proxy selections without changing their artwork status. Git commits/pushes, application promotion and deletion remain separately controlled.

Run `npm run assets:finalize` after the final edit. Every candidate receives full regular local checks, both Game/Dev builds and identity checks. Regression journeys follow the [test-value and budget policy](../CONTRIBUTING.md#e2e-coverage-and-execution-budgets); authoring preparation, visual review and publication remain separate operations. Lighting correctness smoke does not include benchmark sampling unless explicitly requested. A bounded comparison with the pinned inventory selects visual journeys: hero changes require both packages and animation/hero/Game/lighting smokes; room assets require consuming-room browser acceptance; lighting and relief require the Dev package, lighting smoke and consuming rooms; effects require the Dev package and Effects smoke, plus Game and consuming-room checks for runtime effects. Shared helpers, catalog/bake changes, unknown outputs or an unavailable baseline use the full checklist. `npm run assets:finalize -- --full` explicitly requests every journey. The completion receipt records selection reasons and source identities; previous receipt versions require fresh validation.

Equivalence compares validated sorted path/size/SHA-256 inventories, excluding only `pack.json` and `metadata/preparation-inputs.json`. Every runtime file and other receipt participates. Equivalent completion runs full regular checks, both builds and their identities before atomically recording accepted provenance; it needs no duplicate upload or visual acceptance. `--full` still runs every journey. Both candidate and baseline remain leased and are revalidated before pinning. Source-free CI validates the accepted recipe/input hashes and published payload; proving a changed preparation produces identical bytes belongs to explicit authoring finalization. Incremental validation uses the accepted input hashes after reuse.

Finalization prints retained captures and a review identifier. The agent inspects those exact captures at gameplay and enlarged scale, then accepts them using `npm run assets:finalize -- --reviewed <review-id>`. This publishes the existing validated archive, verifies the public download and atomically updates the pin without preparing a replacement. Publication recomputes the selection and rejects missing checks, changed source inputs, changed or expired captures, corrupt archives and failed public verification. It runs `assets:ensure` and pinned asset/binding checks after publication; full regular evidence is reused only while inputs other than the expected pin remain identical. A post-pin verification failure restores the previous pin only if another writer has not changed it. An uploaded release can remain after failure; retirement follows the retention workflow.

Capture directories are returned through structured task results, not parsed from console output. Shared preview-reload checks run once per multi-room finalization batch. Surround timing sampling belongs to `npm run scene:benchmark -- --scene court`; ordinary scene acceptance retains framebuffer, viewport and resource assertions.

For concurrent asset tasks, one coordinating agent finalizes the combined batch after participating owners declare their changes ready. Keep authored inputs stable through validation and publication. Other agents can read and review while waiting, but start no competing preparation/publication and announce any needed edit before changing frozen inputs. Source and candidate identities in the external completion receipt bind all evidence to the reviewed bytes. An interrupted upload can reuse an existing immutable release after validating its public bytes. The receipt and captures stay outside Git within the existing cache limits.

## Current animation treatment

The prepared registration contains clip/direction-specific guarded transition fields, mixed-frame canvas/pivot/density mappings, original holds, bounded presentation offsets and weighted walk holds. The small `authoring/hero-motion.json` recipe owns native-space correspondence markers, reviewed sword segments and visibility, signed rotation, residual offsets and loading/release/settling treatments. Torso markers seed correspondence; they do not establish measured anatomical retargeting or root motion. Original four-direction Weighted Walk holds are preserved; new cardinal runs use reviewed loading holds within their supplied 40-tick cycle, retaining the balanced six-drawing D rhythm.

Runtime defaults to guarded treatment, stabilization and rigid-sword protection with directed action timing. Loaded poses hold before accelerating; release is fast, recovery slows into rest and idle breathes gently. Body coherence remains guarded by silhouette/color checks. Reviewed fully hidden swords permit body-only warp; uncertain short occluded blades, changing visibility and incoherent poses retain held drawings. Rigid sampling follows the reviewed blade segment, respects the native hand/occlusion paint and uses the same signed rotation for color, lighting, shadows and focus. Native projected length changes are retained. Raster sources, pivots and densities are unchanged.

Dev comparison offers Treatment (identical directed timing, corrected versus held drawings) and Timing (directed versus imported rhythm on shared elapsed time). The visual timeline shows directed drawing boundaries, damage windows and lantern pulse; status explains held fallbacks. Seeking is silent and preview controls do not write saves. Field textures stay below 4096 pixels per dimension; generated data and captures remain external. Optical flow cannot supply missing poses: rear death drawings end kneeling, and some partially occluded equipment cannot be safely interpolated.
