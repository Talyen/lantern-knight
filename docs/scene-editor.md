# Scene editor

Run `npm run scene:editor` to open the local browser editor with the pinned artwork. It shares the scene preview server and game renderer within its checkout. For parallel worktrees, set the task’s `LANTERN_PREVIEW_PORT` before starting the editor, preview or checks; [parallel task ownership](../CONTRIBUTING.md#parallel-task-ownership) covers assignment and handoff. A matching preview is reused only for the same checkout and asset revision; filesystem saves stay in that checkout. Keep the command running while editing; stop it when finished if it started the server. The editor's filesystem saves require this local server, even when viewing the developer build.

## Compose a scene

Open a new flat scene or a copy of Graveyard Approach or Ruined Chapel. Search the artwork palette and drag a thumbnail onto the ground. Alternatively, select a thumbnail and click to place it. The palette includes prepared current Clean INK scenery, ground materials/details, characters, animated props, pickups and effects. Current library additions remain labeled TEST or provisional. Whole location/backdrop paintings are browse-only references; rejected, superseded and title/loading artwork is excluded. Search by asset name or clip and filter by category. Thumbnails load only when visible.

Select an object in the viewport or object list. Drag to move it, or adjust position, height offset, size, and mirroring in the inspector. Ground details also support rotation. Clip and Facing select only supplied drawings; missing directions stay unavailable, and asymmetric character artwork cannot be mirrored. Characters are stationary visual objects. Pause/Play and Replay control animation previews without changing scene documents or gameplay. One-shot clips retain their supplied final hold or disappear at their authored end. Grid & snap places roots on half-unit increments. Right-drag or middle-drag pans; scrolling zooms; Fit scene restores the framing. Move hero lets you drag the hero reference for scale without running gameplay.

Duplicate and Delete operate on the selected editable object. Undo/Redo covers composition changes, including inspector edits and hero position. Keyboard shortcuts are Command/Ctrl-Z, Shift-Command/Ctrl-Z, Command/Ctrl-D, Command/Ctrl-S, Delete, and Escape. Text fields retain native editing shortcuts.

New scenes have a rectangular flat foundation with ground material, width, and depth controls. Existing terrain, constructed architecture, paths, and surrounds remain visible and locked. Existing lamps support the placement controls while preserving their authored brightness, range, flame, and smoke. Mounted candles stay attached: moving one adjusts its support-relative offset; moving, scaling, or mirroring its support carries the candles using local offsets. Deleting an editable support deletes its attached descendants in the same undoable operation. Newly placed light-bearing scenery inherits its authored lamp preset. Scenes support three environmental lights; placing another reports the limit without changing the composition. Choose an existing lighting rig and look preset in the scene inspector.

## Save and recover

Save writes an authored scene document. Save As creates a separate draft and never replaces an existing filename. Saving preserves Undo/Redo; after Save As, history belongs to the new draft. New scenes and copies are drafts by default. **Edit Live** opens the actual room document; its persistent banner identifies that saving changes the scenery used by the game. Live changes can also move or remove existing prop collision footprints, so review traversal after editing a blocking prop. New decorations and duplicates have no blocking footprint.

Accepted edits reach local recovery before the preview loads. Reloading offers Restore recovery or Dismiss. Recovery is separate from project files and game saves. Failed writes leave pending edits available, and a failed scene open preserves the current document and file revision. If an agent changes the scene file, saving rejects the stale revision; reload the file or use Save As. Changed base scene definitions or an asset pin require restarting the server. Recovery then validates against the current foundations; review the restored composition before saving. Failed restoration preserves the original recovery.

## Agent integration

Small versioned JSON files live under `authoring/scenes`. The schema and resolver are in [scene-document](../src/content/scene-document.ts). Agents can edit these files directly. Use stable object IDs, catalog asset IDs, and clip IDs; preserve unsupported versions or malformed files rather than resetting them.

Version 3 existing-room documents contain the complete ordered editable scenery list, with protected context supplied by the foundation. Copies snapshot scenery rather than inheriting later live edits. Version 1 documents convert in memory through a bounded migration-only baseline. Version 2 documents retain their scenery and acquire version 3 in memory; saving writes version 3 using the original file revision. Version 3 also records character/effect visual objects and their selected clip/facing. Recovery converts its document and saved snapshot together. Reading does not rewrite files, and unsupported or malformed data remains preserved. The two live documents are imported by the game. Other documents remain authoring drafts until an agent adds the room's gameplay definitions and integrates its resolved visuals. Hero reference coordinates are editor data, not a player spawn or checkpoint.

The editor does not import source-library artwork, create textures, author terrain or architecture, define collisions, place encounters, connect rooms, or provide walking gameplay. Asset preparation and publication remain in the [asset workflow](assets.md).

## Verification

For existing-artwork layout edits, run `npm run check:task -- --scene court` or use `upper-landing` for the chapel. Add `--capture` for a visual redesign and inspect the edited location; the task check includes full regular gates and the selected scene acceptance.

For editor implementation changes, run `npm test -- tests/scene-editor.test.ts` during iteration, then full regular gates and `npm run scene:editor:check` for handoff. The browser check exercises placement, inspector controls, undo/redo, saves, recovery, external-file conflicts, locked fixtures, and rendering resource lifetime. Changes affecting existing-room rendering also require the relevant scene acceptance. Delivery changes add affected builds, identities, packages and journeys under [Contributing](../CONTRIBUTING.md#verification).
